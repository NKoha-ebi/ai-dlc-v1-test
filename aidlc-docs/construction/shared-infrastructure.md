# U01 共有基盤と分離

2026-11-09。設計案。単一チーム・単一作業単位を維持する。[環境比較](patient-support-app/infrastructure-design/deployment-architecture.md)の案2を推奨するが未採用。

共通にするものはソース、型、純粋関数、コンテナーイメージ、Terraformモジュール、合成試験定義。環境別に設定・Auth audience・DB環境ID・サービスアカウント・秘密・メール宛先・予算・state・復元物一覧を分ける。βデータを開発・検証へコピーしない。ローカルからβ資格を使わない。

βと検証のcontrol／recoveryは共用しない。実行枠・予算予約・削除台帳・受信一覧も別。クラウド課金アカウントやCIを共通管理する場合も、IAM・環境承認・短期資格の対象を分ける。共通の課金・組織・CI障害が及ぶ範囲は別プロジェクト化だけで消えない。

案1は開発のcontrol／recoveryを追加し9プロジェクト、案2は6、案3は非本番を共用し6。開発・検証共用の場合は受入期間の構成凍結・試験データ名前空間・削除対象の識別・再試験記録を必要とする。患者データや制御正本を共有して費用を下げる案は採用しない。

制御正本の独立保護先が必要となれば総数・権限・費用を再レビューする。共有の設計はできたが、回復力RESILIENCY-08／11／12の未成立条件は[インフラ設計](patient-support-app/infrastructure-design/infrastructure-design.md)に残る。PBTの実行は文書段階につきN/A、セキュリティ拡張は無効につき省略する。
