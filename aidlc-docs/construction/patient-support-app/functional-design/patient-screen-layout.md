# 患者画面の配置・共通ナビゲーション（レビュー案）

2026-11-02の指示を反映。トップを悩み一覧とすること、指定画像のヘッダーロゴとトップへのリンク、整理途中の移動確認、モード表示と近接する変更操作はユーザー指定。以下の具体的な配置・文言・メニュー構成はレビュー案。画面IDは既存の論理表示単位を使い、全てを別URLにはしない。

## 共通ヘッダーとサイドバー

ヘッダーは画面上部に配置する。左にメニュー開閉ボタン、その右に正式ロゴ。ロゴはワークスペースの「血液がんサポートプロジェクトlogo.png」を縦横比・配色・形状を保って使い、切り抜きや引き伸ばしをしない。リンク名は「悩み一覧へ」。タップ・クリック・キーボードでP03へ移動でき、整理途中は後述の確認を必ず通す。

未ログイン時も同じロゴを表示するが、本人の一覧は取得・表示しない。P03へのアクセスは認証へ案内し、認証後も必要な初期設定を先に完了する。必須同意や認証をロゴ経由で回避できない。

PCはヘッダー下の左にサイドバー、右に本文。スマートフォンはサイドバーを初期状態で閉じ、メニューボタンから開く。開閉で入力やスクロール位置を初期化しない。メニューを開くだけでは離脱確認を出さない。

| サイドバーの項目・表示順 | 移動先・内容 |
| --- | --- |
| 悩み一覧 | P03。トップ画面。作成済み・途中・完了をここからたどる |
| お知らせ・記事 | P12の公開コンテンツ |
| お問い合わせ | P11の本人の送信・履歴 |
| 設定 | P10の設定入口 |
| ログアウト | 下部に配置。未送信入力の破棄確認等は既存BR-04に従う |

現在地は文字と選択表示で示す。履歴だけの独立メニューは置かず、悩み一覧の詳細からP08を利用する。新しい悩みの作成はトップの主操作とし、サイドバーに同等の強いボタンを増やさない。患者用に運営・研究メニューを混在させない。ログイン・登録・必須初期設定中は通常サイドバーを表示せず、必要な案内とログアウト等の許可された操作だけ表示する。

## 悩み一覧の意味・初期状態

既存のSupportSessionを患者向けに「悩みの整理」1件として表示する案。個々の発言や支援モジュールごとの一覧ではない。これにより新しい悩み管理エンティティや件数集計を増やさない。既存P08の履歴・再開をトップから利用する。

各項目には本人の内容から得た短い抜粋、最終保存日時、状態（途中／確認が必要／完了）、適切な次操作を表示する。抜粋がなければ「入力前の悩み」とする。新しいタイトル必須入力やAIによる自動命名は追加しない。未送信の端末下書きはサーバー保存済み項目と区別し、当該端末のみの表示とする。未送信を別端末から再開できるとは表示しない。

0件では「まだ悩みは登録されていません」と作成操作を表示。取得中・0件・取得失敗を区別する。並び順は保存日時の新しい順を案とし、検索・タグ・並べ替え機能は今回追加しない。新規作成時は保存済みの疾患・治療情報を利用し、既存の確認条件に従いP04で確認・修正してP05へ進む。毎回アカウント初期設定をやり直させない。

対話モードは支援ごとのため、設定に全体共通のモード設定を新設しない。各支援の表示付近で変更する。

## 戻る・モード・主操作の配置

本筋のP04〜P07では「戻る」をヘッダーの下、本文領域の左上、画面見出しより前に配置する。ロゴやサイドバーの「悩み一覧」と区別する。スマートフォンも同じ順序とし、ソフトウェアキーボードや固定表示で操作を隠さない。

「戻る」の隣や説明に戻り先を表示する。P04は呼出元の一覧または設定、P05は現在の入力・選択手順に対応した前段、P06は支援選択、P07は直前の支援または選択画面へ戻す。初期設定の先頭には存在しない前段へのボタンを置かない。単なる画面移動でAI生成・内容失効を発生させず、前入力の修正に進む場合は既存の影響確認を通す。

P06では支援名の直下に「モード：短め　変更」または「モード：じっくり　変更」を隣接して表示する。省スペースでも読める文字で示し、アイコンや色だけで表さない。スクロール中も確認できる見出し領域とする案。初回選択は同じ領域で行う。変更操作は近接したボタンで開き、既存のモード保持・次要求からの適用規則に従う。時間数値は表示しない。

## トップへの移動確認

P04〜P07で整理・初期入力を継続中に、ロゴまたはサイドバーの「悩み一覧」を押すと移動前に確認する。未保存変更がなくても、整理途中なら確認する。完了後の閲覧や悩み一覧上のロゴ再操作では出さない。同じ確認を多重表示しない。

文言案：「悩み一覧に戻りますか？」「整理はまだ途中です。続ける場合は、この画面にとどまってください。」保存済み・端末のみ保存・未送信・保存結果不明は実際の状態に合わせて別に示す。

- 初期フォーカスと目立つ操作は「整理を続ける」。閉じる・Escape・画面外タップでも移動せず、入力とスクロール位置を維持する。
- 未保存がなければ「悩み一覧に戻る」を補助操作として表示し、明示選択後のみ移動する。
- 未保存があれば「下書きを保存して戻る」「保存せず戻る」「整理を続ける」を表示する。保存失敗・成否不明では自動移動せず、状態を説明して同一要求の確認・再試行を案内する。保存せず戻る場合は失われ得る入力を明示し、既存の保存済み内容まで削除しない。
- 生成中はその旨も示す。トップへの移動を生成取消・削除・全体完了として扱わず、既存の遅延結果の適用条件を維持する。

上記はアプリ内移動の確認。ブラウザーの閉じる・更新では同一の独自ポップアップが必ず表示できるとは保証しない。その他のメニューへの移動は既存の未送信入力確認を共用し、トップ確認と重複させない。

## 部品・検証への引継ぎ

AppShell・RoleNavigationは認証・初期設定状態に応じた項目とロゴ移動の意図を渡し、画面が直接無条件にトップへ遷移しない。LeaveToTopDialogは作業状態・保存状態・生成状態を受け、続行／保存して移動／保存せず移動を返す。保存は既存C05契約と競合処理を共用し、フロント独自の成功判定をしない。

検証対象：初回登録からトップ到達、初期設定途中のロゴ、通常ログイン後のトップ、0件と取得失敗、一覧から再開、PCとスマートフォンのメニュー、モードの視認性と近接変更、戻り先、保存済みでも途中なら確認、確認取消で入力保持、保存失敗で移動しない、生成中のトップ移動、キーボード操作・ダイアログのフォーカス復帰。実装・実ブラウザー検証は未実施。
