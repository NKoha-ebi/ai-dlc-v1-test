# U01 ドメインエンティティ設計（レビュー案）

質問1〜12のAと追加指定に基づく、言語・DB製品に依存しない設計。既存要件を維持し、本段階で提案する具体値・状態・項目は機能設計承認対象。挙動は[business-logic-model.md](business-logic-model.md)、規則は[business-rules.md](business-rules.md)、画面は[frontend-components.md](frontend-components.md)を参照。

## 共通の意味

Idは不透明識別子、Revisionは各所有対象の更新競合・整合性を管理する保存版、Instantは時点、Dateは表示日付。SupportSession.Revisionはセッション集約の版であり、入力内容のInputRevisionや確認済み内容を識別するSnapshot版とは別。本人・権限はサーバーが確立するContextから取得し、入力された患者IDを信用しない。成功値と業務エラーは区別する。変更要求はRequestKey・期待Revisionを伴う。具体型・HTTPパス・保存トランザクションは後続で定めるが、以下の整合性を実現できない方式は採用しない。

「患者確認」は内容の確認であり医学的妥当性や本人認証の代用ではない。論理IDは組合せキーでの表現も許容し、必ず新テーブルを作る意味ではない。

## 状態と集約境界

### セッションの選択・版・不変条件

選択集合に存在しない種別は「未選択」。選択集合にある種別は現在判定対象RunIdを必ず1つ持ち、未実行もModuleRunの「未実施」として識別する。同じ種別の再実行では本人の選択により現在Runを切替え、過去Runを履歴として保持する。過去の確認済みRunで現在Runの未完了を代替しない。順序変更や明示省略は削除ではない。

全体完了の不変条件は、選択集合の現在Runがすべて有効な確認済みまたは明示省略で、少なくとも1件の有効な確認済みSnapshotがあり、再確認必要な対象が残らず、本人の完了操作が成立していること。未選択種別は判定対象外。具体的な操作可否・遷移の正本は業務ロジックモデルの「修正・複数端末再開・完了」。初回完了時点、現在作業状態、各Snapshotの現在有効性は独立し、履歴だけで現在利用を許可しない。

SupportSession.Revisionの更新対象は、選択・順序・現在Runの切替、入力・参照の保存、ModuleRunの状態・確認済みSnapshot参照、依存失効、セッション状態・初回保存／初回完了記録の確定。画面内だけの未保存編集や外部AI内部状態の変化は、そのままC05集約の保存成功を意味しない。生成結果を集約へ適用する際は期待版と使用した内容版の両方を検証する。

確認済み保存は、新Snapshot保存、Runの確認済み状態・参照更新、必要なセッション状態とRevision更新を、すべて反映するか一つも反映しない単一業務操作とする。読取・画面へ途中状態を公開しない。同一RequestKeyによる結果確認・再送は業務ロジックモデルの「操作の共通順序」を適用する。別所有元を含む状態確認と保存確定の順序保証も必要だが、具体的なDB・トランザクション方式は後続設計事項。

### 依存と利用可能性

Proposal／Snapshotが実際に使った入力・Snapshot・Profileの識別子と内容版を有向の参照として保持する。変更元を直接参照する結果が直接依存、その結果を辿って到達する結果が間接依存。セッションRevisionの変化だけでは全件失効にしない。参照の欠落・確認不能では関連候補を影響なしとせず、確認できるまで現在利用不可とする。履歴保持は許すが、失効・確認不能の版をPDF・研究提供・後続支援へ流用しない。影響判定と作り直し・再確認の順序は業務フローを参照する。

### 撤回・退会と確定境界

ConsentReceipt.Revision／撤回確定版、Accountの状態・Revision、DeletionRequestの受付確定・対象削除世代、ResearchConditionsの版、Projection／AggregateReleaseの元版・同意世代を、対象操作と対応付ける。開示許可は特定要求と特定結果・対象版に限定し、別要求・ページ・結果へ流用しない。撤回・退会・削除受付と許可確定の順序は業務フローの撤回節を正本とする。必要な状態・版を確認してから確定するまでの競合を許さず、確認不能なら新規開示・保存・適用を拒否する。

退会・対象削除受付後のAI結果は、以前の生成受付や開示許可を根拠に保存・適用できない。一時物も削除対象。研究のみの撤回は通常利用のAI保存を停止しない。対象者を除いた集計の再計算と、新しい結果の開示許可は別判定。

### Account消去後の削除追跡

「Account削除済み」はC03の本人情報・資格の消去を表し、関連所有元の物理削除、バックアップ対応、要求追跡保持終了とは別。削除要求の完了は対象範囲全体の消去確認後。追跡の保持期限・起算点はBR-07を正本とする。

以下の記録は既存所有元の処理結果とC09要求の最小追跡であり、新しい閲覧権限・画面を追加しない。削除実行・復元後再反映に必要な既存の内部契約に限定し、運営へ本文や追跡情報一式の閲覧を付与しない。本人対応付けは再反映目的と期間を満たした時点で除去。不透明IDもそれだけで匿名としない。

| 所有元 | 対象と最小追跡・保持目的 | 完了条件と期限参照 |
| --- | --- | --- |
| C03 | 本人情報・資格・役割。要求IDと無効化／消去結果だけ追跡 | 受付で新規利用禁止、本人情報消去はBR-07本体7日。C03完了だけで全体完了にしない |
| C04 | 同意・撤回記録の対象本人情報、再反映用の最小版・結果 | 対象情報消去を確認。再反映用追跡はBR-07の要求追跡とバックアップ条件に従う |
| C05 | Profile・入力・全Run・Proposal・Snapshot・利用／完了記録と履歴 | 対象範囲の本体・派生・履歴の消去結果を確認、7日 |
| C06 | AI要求内の入力、一時結果・失敗物、外部処理先の対象 | 遅延適用拒否と削除結果を確認、7日。外部側の消去確認方式は後続で検証 |
| C07 | PDFと生成中間物・失敗一時物 | 生成後24時間以内の消去、削除受付で先に利用禁止。本体削除7日も満たす |

各元の削除対象にはProjection・複製・中間データ・失敗一時物を含み、保持しない対象も一覧上で根拠を確認する。処理担当の参照は対象要求・範囲に限定し、本文を追跡へ転記しない。バックアップ対応は失効日到来だけでなく、方式に応じ対象残存・復元可能性の消去確認が必要。再反映用最小追跡は対象を含むバックアップ対応完了まで保持する。期限超過で必要性が残る場合は未解決として記録し保持延長を見直し承認へ回す。無期限保持や既存期限の自動延長は認めない。

### 既存の状態遷移

- Account：利用前→利用可能、利用可能↔停止、利用可能／停止→退会処理中→削除済み。停止解除で同意や研究条件を有効にしない。
- 同意：未記録→確認待ち→有効→撤回済み。研究文面・対象版の不一致は利用不可。再同意は別の意思記録とし、過去の反映処理を巻き戻さない。
- 撤回：正本記録失敗／撤回確定・反映待ち／一部反映／反映失敗／反映完了。同意の有効性は「撤回確定」で失効し、反映完了を待たない。
- セッション：編集中→確認待ち→完了→再編集中→再完了。初回完了時点は保持する。再確認必要な派生結果は新規PDF・提供に使わない。
- 生成：受付→処理中→成功または失敗。入力版変更・対象削除なら失効。生成成功とC05保存成功は別。
- 問い合わせ：受付→対応中→回答済み。確定返信がなければ回答済みへ変更不可。返信下書きは患者から不可視。
- 記事・お知らせ：下書き→公開→非公開、公開中の編集→別下書き→再公開。公開時の期待版を確認する。

WithdrawalRequest・DeletionRequestの所有元別の状態更新は対象要求・対象版を照合し、古い完了通知で新しい要求を完了させない。具体的な非同期基盤の採用はここでは決めない。

## Testable Properties（検証可能な性質）

保存形式への往復は、Id・選択状態・Revision・日本語・空文字・未回答を保存前後で保持する（往復）。日時の表示変換は元時点を別途保持し、月境界の分類が安定する（不変条件）。AccountIdとSessionIdが一致しない対象参照は拒否する（不変条件）。Withdrawalの反映状態をどう変更しても撤回済み同意が有効にならない（不変条件）。状態列挙と版参照の生成器をPBT対象とし、DB I/Oや実AIは通常の統合検証で扱う。

## 運営用集計の返却モデル（US-28）

OperationsAggregateは永続エンティティではなく、BR-11に従う返却用データとする。対象月、期間開始、集計基準時点、利用者数、完了数、評価合計、評価回答件数を持つ。平均は合計÷件数から導出し、0回答は算出不能。画面向け平均の丸め方は表示設計で定め、合計・件数を丸めない。患者ID一覧・本文・AI案・個別評価一覧は含めない。

元記録は既存C05 Sessionの所有者・初回保存日時・初回完了日時とC08 Ratingの最新確定評価・元版。評価履歴や集計用患者コピーを追加せず、既存の版・監査保持要件は維持する。削除適格性・アカウント状態は各所有元の契約で確認する。OperationsAggregateをC14 AggregateReleaseに転用せず、外部開示履歴の保持責務も置き換えない。

原則は取得時算出・非永続。参照整合方式、索引、キャッシュ等は後続の非機能・保存設計で選定する。対象者・少人数表示の未確定条件はBR-11を正本とする。
