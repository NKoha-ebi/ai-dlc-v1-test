# U01 業務ロジックモデル（レビュー案）

回答は全12問Aを基本とし、複数端末再開・UI追加指定を反映。以下の状態・上限は設計レビュー案。[domain-entities.md](domain-entities.md)と[business-rules.md](business-rules.md)を合わせて適用する。

## 操作の共通順序

認証前の登録・ログインはC03入口で入力と対象公開制御を検証する。認証後はContext→C03の利用状態・役割→対象C12の可否→必要なC04同意→所有元の本人・業務状態→操作実行の順を基本とする。研究はC14の条件・範囲確認を加え、所有元も制約を維持する。認証なし・権限なしの相手へ対象の存在・本文を返さない。入力検証成功だけで操作許可にしない。

変更は対象と期待版を照合して保存し、保存結果と更新版を返す。同一RequestKey・同一操作内容の再送は同じ結果へ収束させ、同じキーで異なる内容は拒否する。通信断は成否不明として結果を照会／再取得し、新規要求を無条件に作らない。同期／非同期の応答方式は非機能設計で選ぶ。

## 同意撤回：調整・失敗・反映前の利用拒否

1. 同意撤回アプリケーションサービスが本人・対象目的・同意版を確認する。通常利用と研究の撤回を区別し、研究撤回だけで患者の通常利用を停止しない。
2. C04が撤回済みの正本と、反映すべき対象を含む追跡要求を同じ論理的確定操作で永続化する。両方を確定できなければ成功を返さない。結果不明時は同じキーで実状態を照会する。
3. 撤回確定と研究データの開示許可確定を対象同意について順序付ける。撤回より後の開示確定は拒否する。必要な同意を照会できないときも拒否する。
4. 研究検索・個別取得・集計提供は、取得前の条件確認に加え結果の開示確定直前に同意版・研究条件版を確認する。単なる「確認してから送信」の間に撤回が割り込める方式は不可。対象同意の排他または同等の原子的な開示許可契約で順序を保証する。具体方式はNFR・保存設計で選定する。
5. キャッシュ・Projectionは許可の正本にしない。集計は全対象の適格性を確認できる同意世代と照合し、世代変更なら再計算・再抑制する。処理中に撤回した対象を除外すると人数・差分条件が変わるため、取得済み結果の使い回しはしない。
6. サービスがC14と派生データ等の必要な所有元へ撤回確定版を渡し、各結果をC04の追跡要求へ保存する。C04自身が全所有元の保存領域を読む構成にはしない。
7. 途中失敗は反映失敗として記録し、撤回状態を維持して未完了対象だけ再試行する。対象要求・同意版に基づく重複排除により、成功済みの再実行も同じ制限へ収束させる。運用側は本文を含まない失敗記録・観測で検知する。具体の再試行間隔・警告期限はNFR設計へ。
8. 全対象の処理結果を確認して反映完了とする。本人表示は「撤回済み／関連データへの反映中」を分離する。新しい再同意があっても、古い要求で新しい許可を上書きしない。実データの再利用範囲は承認済み研究方針に従う。

既に開示確定した結果や相手に渡った情報の回収を保証しない。撤回以後の新規開示を止める境界であり、既開示データ・集計の取扱いは研究条件の承認事項。ダウンロード済みPDFの遠隔消去も行わない。これらを理由に将来の利用拒否を遅らせない。

## 利用開始・患者整理

- US-01・02：対象15〜39歳の登録・認証→年齢条件に応じた同意確認→利用開始。15〜17歳の本人・保護者等の確認が未了なら整理機能を開放しない。確認方法・文面・責任者の実運用承認は別途必要で、患者自己申告だけを確認済みの根拠にしない。
- US-03：がん種・治療時期・治療内容を保存。未入力と回答拒否を分離し、治療中の治療内容は選択必須。変更版を後続支援の参照版にする。
- US-04：入力保存→最小入力で抽出・構造化要求→未確認案表示→患者が修正・確認→確認済み版保存。AI案だけで支援選択・PDF用内容の確定をしない。
- US-05：本人が指定した関心分類と確認済み入力に基づく明示ルールで候補を出す。複数候補・候補なしは全5支援から本人が選べる。自由記述の曖昧なキーワードだけで自動遷移しない。

## 5支援の入力・出力・遷移案

各支援は入力→構造化／候補案→編集・選択→患者確認→保存。同じ支援を再実行でき、省略・順序変更を許容する。医学判断の確定は行わない。

| 支援・対応 | 入力とAI範囲 | 確認後の出力・候補ルール |
| --- | --- | --- |
| M1 価値観 US-06 | 大切なこと・避けたいこと。本人の記述から価値観を抽出・要約 | 価値観の文と元入力参照。「大切にしたいことを整理したい」の関心指定で候補化 |
| M2 希望 US-07 | やりたいこと・望む状況。曖昧な希望を構造化し不足情報を質問候補として表示 | 本人が確認した希望。希望が曖昧でも推測で確定しない。「やりたいこと」で候補化 |
| M3 懸念 US-08 | 困りごと・心配・本人選択の疾患／治療情報。懸念と確認が必要な事項を整理 | 困りごとと質問候補。「心配・困りごと」で候補化。治療変更案は出さない |
| M4 実現プラン US-09 | 本人確認済み希望、任意の価値観・懸念、本人記入案。小さな非医学的行動の候補を最大3件生成 | 本人が選択・修正した案。医療上の可否は保証せず医療者確認へ分離。「行動を考えたい」で候補化 |
| M5 医療者確認 US-10 | 確認済み希望・懸念・選択行動、本人の質問。質問文の整理・重複統合 | 本人確認済み質問。「医療者に聞きたい」で候補化。医学的回答を確定しない |

生成案が意図と違えば編集または再生成する。M4に希望がなければ希望を同じ画面で記入・確認でき、M1やM2の完了は強制しない。手入力で確認済み内容を作る経路を残す。結果の再生成が必要な戻る修正では、その完了まで関連結果を未確認として扱う。

生成上限案：初回を含み1支援実行につき5回、セッション全体30回の実AI呼出し。生成要求の受付キーが同じ再送は追加消費しない。外部AIに送信した失敗試行は消費、送信前検証拒否は消費しない。戻る修正の必須再生成も同枠を使い、枠不足なら確認済みへ進めず不足を表示する。新しいセッションで継続する際も対象結果の作り直し・再確認を省略しない。費用対策としてのアカウント別制限はNFR設計で別に選定する。

## 修正・複数端末再開・完了

US-11：戻る確認の取消は入力・結果不変でAPI未呼出し。承諾後は前入力を保持し修正できる。変更時は依存する生成案を再作成し本人が再確認する。入力版・参照版の依存を辿って影響範囲を求め、無関係な支援は維持する。完了済み版は履歴とし、新しい派生版を確定する。

US-12：各端末はサーバー保存版と未送信入力を区別する。同じアカウントで別端末にログインした場合、サーバー保存済みセッションと版を取得して続ける。端末Aの未送信分を端末Bで見られるとは表示しない。リアルタイム同時編集は実装しないが、並行して古い版から保存する競合は処理する。

競合案：期待版不一致なら更新を拒否し、現在のサーバー版と自端末入力を表示する。自端末入力を保持したまま「サーバー版から続ける」または差分を本人が新しいサーバー版に手動反映して保存する。無条件上書き・自動マージはしない。新しい版取得後にも再競合したら同じ手順を繰り返す。端末内永続保存が失敗した場合は「この端末にも保存できていない」と明示し、タブを閉じる前の保存を案内する。

完了案：選択した支援のうち1つ以上に内容確認済みの結果があり、選択中の実行が確認済みまたは明示省略で、再確認必要な結果が残らないとき、本人が「今回の整理を完了」を押せる。5支援すべてを要求しない。初回完了時点を固定し、再編集・再完了でも件数を増やさない。

## PDF・評価・削除

US-13：本人→C05の特定確認済みスナップショット取得→所有・版・確認状態を検証→C07でプレビュー／取得。掲載対象の未入力は「記載なし」とし、氏名・画像は載せない。基本1ページに収まらない場合は本文を無断で省略せず複数ページとなる旨を表示する案。生成後の一時成果物取得でも同じ許可を再確認し、共有URLによる無認証取得は追加しない。PDF失敗は入力・保存済み結果を変更しない。

US-14：C05が本人・完了資格を返し、C08が最新1評価を保存。完了後の再編集中は新評価を保留し、再完了後に再回答できる。既存評価は初回完了済みセッションの最新値として保持する。平均×10・未回答／途中離脱・0件算出不能は規則に従う。

US-15：C09の受付と同時に対象の新規利用を禁止する削除状態を確定し、所有元一覧を追跡→各元が本文・派生物を削除／制限→部分失敗を再試行→全対象の期限内処理を検証→完了。退会では先にC03が資格を無効化する。遅延AI・保存再送が削除済みデータを復活させないよう対象状態と世代を照合する。削除状態を確認できない書込・開示は拒否する。復元時も削除・撤回の最新記録を適用するまでは開放しない。

## 運営・公開・問い合わせ

US-16・17：C10は運営権限を検証しC03の許可された契約で状態・研究権限を更新。対象の変更前後・実施者・結果をC16へ記録。運営権限だけでC05本文・C14研究データを取得しない。

US-19：本番変更ごとに目的・対象・影響・検証・実施者・承認者・切り戻し条件・事後結果を開発運用記録へ残す。専用変更管理画面は追加しない。

US-22・26・27：C11でお知らせ／記事の下書きを保存→公開対象版と確認状態を照合→公開版に切替。記事は確認担当が内容・医学情報の確認結果を記録した版のみ公開可能とする案。確認担当の体制未確定なら該当実記事の公開を止める。患者の一覧・詳細はC12可否とC11公開版を取得し、非公開化後の新規取得では本文を返さない。作成者に公開権限がない等の追加役割は独自に新設しない。

US-23：公開制御の受付後、公開停止の確定時点を境に対象操作の新規受付を拒否。既に受理した保存は保存結果を確定し、既に始まったAIは内部処理を完了しても対象停止中は結果の開示を保留する。新規AI・PDF・評価・研究・コンテンツ取得は停止対象なら拒否する。保存済み状態は保持し、未送信入力も保持して再開を案内する。再公開は専用の認証・運営権限付き制御経路で行い、通常停止対象から除外する。C12自体の障害復旧はNFR／インフラ設計へ。

US-24・25：本人送信キーを記録して受付→運営が対応中へ→自由記述下書き→返信確定と回答済みを同時に確定→本人の履歴で閲覧。同一キー再送は同一受付、異なる本文なら拒否。送信失敗の入力は保持。確定返信の追加・改訂、添付、アプリ外通知は本案で追加しない。変更希望があれば範囲変更として確認する。

## 研究・提供

US-20・21：C14条件の全項目・承認根拠・文面版が承認済み、C03研究権限とC04対象同意が有効な範囲のみ、元所有元の許可Projectionを取得する。検索・個別取得・ページング・件数にも同じ制限。識別情報除去を匿名保証と呼ばない。根拠登録は信頼された内部契約の反映として定義し、新しい運営承認権限や画面を追加しない。主体・手続き未確定の間は合成データでのみ動作検証する。

US-18：対象目的・固定期間→同意済み集合→C05利用／完了記録とC08最新評価→許可3指標→人数・差分抑制→開示直前の撤回整合→運営が閲覧。同意変更や削除後は既生成結果をそのまま返さない。提供形式・外部送信は未選定であり、この案からCSV・製薬会社アカウントを追加しない。

## Testable Propertiesと検証例

| 対象 | 性質・カテゴリ | 通常シナリオ／境界 |
| --- | --- | --- |
| C03・C04 | 別人・無権限・未同意の許可なし（不変条件） | 他人ID・停止・15／17／18歳・研究のみ撤回 |
| C04撤回 | 反映失敗で同意有効へ戻らない、撤回後開示確定なし（不変条件・モデル比較） | 2所有元中1件失敗、処理中撤回、再同意後の旧反映 |
| C05候補・版 | 同じ入力のルール判定は同じ候補、古い入力へ生成案適用なし（不変条件） | 候補なし／複数、5支援省略、取消時APIゼロ |
| C05再開 | 保存競合で両端末の入力を無断消失させない（不変条件） | A保存→B旧版保存拒否→手動反映 |
| C06 | 対象外タスク・削除済み対象・古い版の確定なし（不変条件） | 不正型・外部失敗・遅延結果・上限境界 |
| C07 | 出力項目が確認済み版に対応（不変条件） | 氏名・画像不掲載、生成失敗でも入力不変 |
| C08 | 最新1件・整数範囲・0件算出不能（不変条件） | 再回答、1点／10点、空集合 |
| C09 | 再試行で削除済み情報の復活なし（不変条件・冪等） | 部分失敗、復元後再反映、旧AI応答 |
| C10〜14 | 無権限公開・下書き開示・未承認研究利用なし（不変条件） | 直接指定、研究者のみの運営操作、9／10人・差分推定 |
| C15 | 保存変換の往復保持（往復） | 日本語、未入力と回答拒否、空リスト、版 |
| C16 | 本文・認証秘密を無条件に複製しない（不変条件） | 成功・失敗・再送・記録障害 |
| C01・C02 | 状態導出・入力検証の純粋部分の不変条件。描画自体はPBT性質なし | キーボード・空状態・実画面はPlaywrightと手動確認 |

実AIの内容品質・医学判断をしないことは合成シナリオを含む評価で検証し、PBTの代用にはしない。競合の順序保証は通常の並行統合検証も必要。
