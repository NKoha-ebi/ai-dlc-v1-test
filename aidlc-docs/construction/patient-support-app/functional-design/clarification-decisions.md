# 機能設計・確認回答の決定事項

19回答と追加3回答（1A・2A・3A）を整合確認し、関連設計へ適用する。今回具体化した条件の正本は本資料。旧資料の未確定記述は以下の範囲で置き換える。機能設計全体の承認・実装・実データ有効化は別である。

## 支援の最低条件

| 支援 | 必要な情報 | 任意の補足 |
| --- | --- | --- |
| M1 価値観 | 大切にしたいこと、または避けたいこと1件以上 | 理由・具体例 |
| M2 希望 | 希望1件以上と、その具体的な場面または本人にとっての意味1件以上 | 期限・実現方法 |
| M3 懸念 | 心配・困りごとの対象1件以上と、困る場面または生活への影響1件以上 | 原因・程度 |
| M4 実現プラン | 確認済み希望と、対応する本人選択・修正の非医学的行動1件以上を確認済み保存に必要とする | 時期・協力者・障壁 |
| M5 医療者確認 | 質問または医療者に確認したい事項1件以上 | 背景・理由。対象・場面・行動等を可能な範囲で具体化 |

M1・M2・M3・M5は成立時に未確認まとめ案を作成できる。M4は希望を確認して行動候補を提示し、本人の選択・修正後に保存条件を照合する。どの支援も本人による内容確認・保存を経て確認済みになる。不足時は補足・下書き保存・明示省略へ案内し、「分からない／答えたくない」を推測で埋めて確認済みにしない。

M5では「何に注意するか」「ある行動をしてよいか／避けるべきか」「相手に何と伝えるか」を医療者へ尋ねる質問文へ整理する。アプリが医学的な可否を回答しない。具体化には本人の情報を使い、不明な対象を作らず、背景・理由を新たな必須項目にしない。

## 対話と手入力

短めは最低条件成立で未確認まとめ案へ進む。じっくりは任意の理由・場面・優先順位等を深掘りし、本人が継続／まとめを選べる。最低条件をモードで省略しない。固定往復数や時間で打ち切らない。

M1〜M5は初回・作り直しとも手入力で最低条件・現在入力版・有効参照・依存先再確認・本人確認を満たせば、確認済み保存と全体完了資格の対象になる。AI実行自体をこの5支援の必須条件にしない。古い結果をそのまま再確認して有効に戻さない。P05b抽出処理は本変更対象外。全体完了は従来どおり、確認済み結果1件以上、選択Run全件が確認済みまたは明示省略、再確認残なし、本人の全体完了操作を必要とする。

## 他支援からの本人選択式引継ぎ

[採用済みの項目表・P06操作詳細](clarification-answer-review.md)を追加質問3Aで採用した。以下は確定条件である。

| 対象支援 | 他支援の有効な確認済み項目から選べる範囲 |
| --- | --- |
| M1 | なし |
| M2 | M1価値観 |
| M3 | なし |
| M4 | M1価値観・M2希望・M3懸念 |
| M5 | M2希望・M3懸念・M4選択行動 |

P06冒頭で支援名・目的に続け「この支援に引き継ぐ内容」を置く。項目単位・初期未選択で、「この内容で進む／引き継がずに進む」を保存して対話へ進む。候補なしでも進め、M4の希望不足は同じ支援内で記入・確認できる。他支援の完了を強制しない。途中は「引継ぎ内容を変更」で同じ欄を開く。既存配色・カード・上部固定モードを維持し、独立画面やURLは追加しない。

CarryoverSelectorは候補・項目IDと元Snapshot版・保存済み選択版・操作可否を受け、未保存選択・dirty・保存中／成功／失敗／成否不明／競合を保持する。ConversationControllerがC05の保存・再開を調整し、Presenterは描画する。選択保存だけではAI生成せず、取消・開閉だけではAPI・生成・失効を起こさない。失敗・成否不明では選択を保持し既存要求を確認する。

C05所有のModuleRunは未確定／確定空集合／確定選択集合と、選択内容版・項目ID・元Snapshot内容版を保持する。独立DB・新テーブルは必須としない。選択保存はContext・RunId・選択項目と元版・期待Revision・RequestKeyを受け、保存済み選択と版・操作可否を返す論理契約とする。既存保存契約への統合可。

C05が本人・同じSession・対象Run・許可表・必要性・現在有効性を検証し、C06へ許可済み入力だけを渡す。フロントの任意IDを信用しない。GenerationRequest・GeneratedProposal・ConfirmedSnapshotは実際の選択内容版と参照版へ対応付ける。確定変更で版を更新し、旧選択の遅延結果を適用しない。実依存だけを再確認へ渡し、確認済み内容を上書きしない。再開は保存済み選択を復元・再検証し、失効した参照を黙って新しい版へ置換しない。

未選択の他支援結果は送信しない。今回回答・初期入力・現在Runの直近会話とは区別する。M1・M2に疾患治療情報を通常送らず、M3・M4・M5には必要な当該悩みの項目のみ使用する。別の悩み、別Runの会話全文、未確認案、失効結果、タイトル・メール・認証秘密・問い合わせ・運営本文は送らない。

## 入力予算・数値上限

AI入力予算を超える場合は送信停止・理由表示・入力保持とし、本人による短縮・下書き保存・上記条件を満たすM1〜M5の手入力へ案内する。必須情報の無断省略・自動要約・全文切替はしない。保存は成功確認前に保存済みと表示しない。

直近3往復は合成会話の比較試験候補として採用し、実利用値とはしない。入力予算は提供元選定後に検証し、往復数とともに品質・完遂率・費用を評価して採用値を確認する。AI初回込み5回／支援実行・30回／セッション・M4候補最大3件は暫定検証案を維持する。送信試行計数・成否不明の枠確保・再送冪等性は維持する。

悩みタイトル50文字・単一質問1000文字を指定値として反映する。本文4000・返信4000・記事タイトル100・記事本文10000文字は今回一括承認せず従来提案を維持。単一質問と本人回答の上限は別。文字はUnicodeのユーザーが見える単位とし、超過の無断切捨て・前後空白除去で通さない。具体計数方式は後続で統一する。

## 利用者・内部集計・研究

登録時15〜39歳は維持し、登録済みなら40歳以降も新しい悩み作成を含め通常条件で継続利用可能。15〜17歳に必要な本人・保護者等の同意は、承認手続きが整うまで確認済みにせず、該当整理機能を有効化しない。

運営用当月集計は利用・完了・整理実感の把握とサービス改善に限定する。既存の運営権限で閲覧し、研究・外部提供・個人評価へ転用しない。研究未同意者・研究同意撤回者を含め、研究同意を内部集計条件にしない。アカウント利用停止者も含める。退会者・削除受付後の対象は除外し、再取得と返却前検証でも適用する。利用停止・研究未同意／撤回・退会は別状態で、研究同意撤回だけでアカウントを利用停止にしない。

少人数でも既存3指標を表示する。利用者数・初回完了セッション数・最新確定評価の平均というBR-11の定義、当月・基準時点・保存層集計・原則非永続を維持する。平均0回答は算出不能とし、0件・失敗とは区別する。患者本文・個別明細・新指標は追加しない。

内部集計の対象・目的・少人数条件は今回解消した。通常利用の同意・説明との整合、機能設計全体の承認、実装・権限・削除反映等の検証前は実データ集計を有効化しない。外部用D05・BR-09の期間・人数・差分条件、研究募集／研究実データ無効は維持する。
