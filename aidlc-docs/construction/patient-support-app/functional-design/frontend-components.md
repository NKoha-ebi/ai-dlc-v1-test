## フォーム検証・確認操作

再設定依頼はメール形式を検証し、登録有無を明かさない受付表示にする。リンクはC03で期限・最新世代・未使用を検証し、新パスワードは既存の登録時規則と確認欄一致をサーバーでも検証する。成功時は当該端末の認証表示・保護データのキャッシュを解除し、他端末も旧資格による操作をサーバーで拒否する。下書き削除とは区別し、再ログイン後の本人確認なしに表示しない。

タイトルは任意。空欄・空白のみは未設定として抜粋（なければ「入力前の悩み」）へ戻す案。タイトル上限は50文字とし、自由記述回答上限と区別する。本人・対象・期待Revision・RequestKeyをC05で検証し、取消ではAPIを呼ばない。タイトルをAIへ送らない。

ProposalReview・ModuleEditorは生成受付時の入力・参照版と要求IDを保持する。整理中も入力・回答履歴・画面位置を保持し、結果領域と送信ボタンだけを処理中表示にする。ボタンは回転アイコンと「整理中…」を表示して重複送信を防ぐ。処理状態を読み上げ通知し、動きを減らす設定に対応する。失敗・成否不明でも入力を消さず、同一要求の結果確認へ案内する。入力を編集した場合、古い版の結果を現在入力へ自動適用しない。生成中の移動確認・モード変更は既存規則を維持する。

追加検証はpatient-screen-layout.mdに従う。同時リンク使用でも成功は一回、成功後の全旧資格は拒否、タイトル変更だけでは内容版・完了・件数は不変、生成中・失敗後も入力保持という性質を後続テストへ引き継ぐ。

患者の自由記述・問い合わせ・返信は空白のみを未入力として扱い、内容を黙って書き換えない。D08の上限はUnicodeのユーザーが見える文字単位で揃える案とし、サーバーとフロントで一致させる。詳細な文字数方式・バイト上限は技術選定で確認する。欄ごとにラベル・必須／任意・エラーを関連付け、送信時はエラー要約と最初の不正欄へ移動する。サーバー検証を必須とし、UI検証だけで受理しない。

- 疾患フォーム：治療中の内容必須、回答拒否と未入力を区別。現在非表示の旧値を無断で確定しない。
- 支援入力：参照元版・本人確認状態を表示。AI案は「未確認」、確認保存後に「内容確認済み」。生成完了だけで保存済みと表示しない。
- 全体完了：C05が、選択支援の現在Runに有効な内容確認済み結果が1件以上あり、現在Runがすべて確認済みまたは明示省略で、再確認必要が残らないと判定した場合に本人が別の完了操作を行う。未実行を自動省略せず、全5支援を強制しない。P07に阻害支援・理由・戻る操作を表示し、フロントだけで確定しない。
- AI上限：初回込み支援実行5回・セッション30回の各残枠／不足を別表示。現在入力版・参照版に適合した案は上限だけで確認保存を禁止しない。作り直し未了・古い参照版なら下書き保存と確認済み保存を区別し、進めない理由を表示する。手入力は既存経路を維持し、業務側変更案の現在版・必要項目・依存再確認条件をC05が満たした場合にのみ確認保存可能。M1〜M5はAI枠不足でも必要条件を満たす手入力で確認保存可能。P05b抽出は別扱い。古い結果をそのまま確認済みに戻さず、上限回避の新セッション・再実行を推奨しない。
- 評価：1〜10の整数選択、未回答に0を使わない。再回答は「以前の回答を置換」と表示する。
- 返信：送信前に患者へ公開される本文と対象を確認。下書き保存と返信確定を別の操作にする。
- 公開・停止・権限変更・削除・撤回・退会：対象・変更後の状態・影響を確認する。確認ダイアログの取消はAPIを呼ばない。撤回と削除を同じボタンにしない。
- 記事：タイトル・本文・種別、公開対象版と確認状態を検証。公開中の本文を編集中の下書きで置換しない。

## 共通の表示状態

支援の進行分類は以下の画面表示であり、新たなModuleRun業務状態は追加しない。AI生成処理状態と保存状態を別の表示領域・説明で示す。省略はデータ削除ではない。

| 画面上の分類 | 選択とModuleRun状態の対応 |
| --- | --- |
| 未選択 | 選択集合にない種別。完了判定対象外 |
| 選択済み・未実行 | 選択集合にあり現在Runが未実施 |
| 実行中 | 現在Runが編集中または確認待ち。「編集中」「本人確認待ち」を併記して区別 |
| 確認済み | 現在Runが確認済みで、対象結果が現在有効 |
| 省略 | 本人が明示し現在Runが省略。過去内容の削除を意味しない |
| 再確認必要 | 現在Runが再確認必要。参照確認不能も利用不可理由を明示し、確認済み表示にしない |

AI生成中は上表の進行に併記する処理状態であり、Run状態へ「生成中」を追加しない。保存状態も画面内入力のみ／端末保存成功／サーバー保存成功を識別し、端末保存だけで別端末再開可と表示しない。

| 状態 | 表示と許可する操作 |
| --- | --- |
| 初期・未入力 | 目的と最初の操作を説明。入力を要求する理由と任意項目を表示 |
| 空一覧 | 「保存済みの整理はありません」等、空である理由と作成／戻る操作。取得失敗と区別 |
| 読込・処理中 | 操作名と処理中を表示、二重実行を防ぐ。AI整理中は上記の部分表示を用い、結果領域と送信ボタンに限定して「整理中…」を表示。入力・履歴・画面位置を保持 |
| 成功 | 保存済み版・日時または受付結果を表示。削除・撤回の受付と反映／消去完了を別にする |
| 入力不正 | エラー要約・該当欄・修正方法。入力内容を保持 |
| 競合 | 自端末内容とサーバー版の違い、手動解消操作。自動上書きなし |
| 通信断・結果不明 | 「保存できたか確認できません」と表示。同じ要求の結果確認・再接続後再取得 |
| 外部AI・PDF失敗 | 失敗対象と再試行。下書き・確認済み閲覧を維持 |
| AI生成上限到達 | 支援実行5回／セッション30回のどちらが不足か表示。閲覧・編集・下書き保存を各条件下で維持し、現在版適合の確認保存・C05完了資格を満たす全体完了は一律禁止しない。作り直し未了やAI必須範囲の枠不足なら確認済み保存・全体完了へ進めない理由を表示。入力・保存済み結果を失わせず、画面全体を操作不能にしない |
| 利用停止・権限拒否・同意不足 | 状態と許可された次操作だけ表示。保護対象本文・存在情報を漏らさない |
| 研究無効・集計抑制・0回答 | 条件未承認／提供不可／算出不能を区別。抑制対象の実数を表示しない |
| セッション失効 | 再ログイン後サーバー版を再取得。別人へ端末下書きを表示しない |

保存・成功メッセージは補助技術で通知できる。通知のために画面フォーカスを毎回奪わない。再試行の対象を明示し、別の新規要求を無条件に作らない。

端末保存まで失敗した場合は「この端末にも保存できていない」と示す。画面内保持はリロード・終了・クラッシュ後の復元保証ではない。復元は同じ本人の安全な領域で端末保存成功した範囲のみ。通信断・競合・API拒否でも可能な範囲で入力を保つが永続保存を保証しない。ログアウト時はBR-04の破棄確認・取消・共有端末方針を維持する。

## ナビゲーション・レスポンシブ・アクセシビリティ

P03を患者側の基点とし、現在地・履歴への戻り先を維持する。通常のページ移動で未送信入力がある場合は保存／破棄／移動取消を選べる。これは「戻って前入力を修正する」業務操作とは別で、ブラウザーの戻るだけで生成を呼ばない。復帰時に公開可否・権限・保存版を再取得し、古い画面状態を許可根拠にしない。

スマートフォンは1列、PCは必要に応じ一覧／詳細や左右比較を併用。表は見出しと値の関係を保った一覧・カード表示を用意し、横幅不足で操作が消えない。狭い画面でも編集・確認・エラー・主要操作の順序を維持する。正確な幅・余白・配色は表示レビューで決める。

見出し階層、ラベル、意味のあるリンク、キーボード順序、フォーカスの可視化、モーダル内のフォーカス管理・閉じた後の復帰を設計条件とする。色だけで成功・失敗・選択を伝えない。拡大時の読める配置、エラーの関連付け、読み上げ可能な処理状態を確認する。自動チェックだけで使いやすさやアクセシビリティの達成を宣言しない。
