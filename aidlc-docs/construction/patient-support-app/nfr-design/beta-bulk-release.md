# β版の一括公開・更新方式

2026-11-13。約20人で試用するβ版について、ユーザーがCanaryを取りやめ一括公開することを明示決定した。本書を配備方式の正本とし、過去のCanary回答・段階配備条件に優先する。初回公開と以後のβ版更新の双方に適用する。

## 決定と変更範囲

実利用の5%→25%→100%配分、各段階の昇格判定、3段階分の同一受入試験を廃止する。公開前受入→更新時の計画停止→一括切替→実環境確認→一括開放→集中監視とする。初回公開は既存利用の停止が不要だが、公開前受入と開放判断は同じ条件で行う。

一括切替は利用者への公開単位を指す。比率100%の設定だけで旧処理・旧接続が消えたとは判断しない。アプリと最終ゲートは独立配備を維持し、更新対象を固定する。通常アプリだけの更新で、変更しないゲートを毎回更新することは要求しない。新旧アプリの契約・DB互換は切替中処理と切り戻しに必要なため維持する。

## 公開前の受入

承認するコンテナーダイジェスト・依存・設定版・DB互換範囲を固定し、検証環境で同一成果物を試す。通常の認証・認可・DB・送信制御を通る合成データを用い、患者本文を使わない。PRの型・静的検査、例示テスト、部分PBT、Emulator結合、ビルド、合成E2Eは維持する。

一覧・相談再開・下書き保存・確認保存・設定保存・運営検索の6 APIを各確定100件以上、合計最低600件試す。成功率99.5%以上・p95 2秒以内をAPIごとに満たし、安全試験にも合格してから公開判断する。旧方式の3倍の1800件は要求しない。正常入力・期待業務結果・期限・送信計画を試験前に固定する。

AI・PDFは各10試行、合計20試行を公開前に一組実施する。3段階分の60試行は要求しない。内訳と安全条件は維持する。

| 種別 | 各件数 | 必須確認・合格条件 |
| --- | --- | --- |
| 正常系 | 4 | 結果表示まで60秒以内、所定の出力形式・対象・版・保存／表示条件を満たす。AIの4件中最低1件は実AI経路、PDFの4件は実PDF生成経路を通す |
| 時間切れ | 2 | 制御可能な依存先で60秒超の待機と依存先タイムアウトを各1件。60秒時点の所定の状態表示、要求開始から5分以内の所定終端を確認し、異常系に正常結果60秒以内を要求しない |
| 重複配送 | 2 | 実行中・終端後の再配送を各1件。外部AI二重送信、業務結果・副作用の重複がなく、期限・終端状態が維持される |
| 遅延結果 | 2 | 5分終端後の結果到着と、取消し等による終端後の結果到着を各1件。終端を覆さず、遅延結果の保存・表示・副作用を拒否する |

実AI失敗を模擬成功で相殺しない。必須ケース未実行・不合格なら公開を保留する。実AI実行の費用と件数を分離して記録し、別途実行許可を得る。今回の文書変更は実AI送信・課金の許可ではない。

通常APIの成功率分母は正常入力の全確定試行、成功は期待する業務結果を確認できた試行。5xx・予期しない拒否・タイムアウト・通信断は失敗とし、p95は失敗を正の無限大相当として含む昇順ceil(0.95×件数)番目。成功時の時間は受付から応答完了まで。期待する認可拒否・競合拒否は別の安全試験とする。到達前通信断は送信記録で失敗に数えるが、到達必須100件には加算しない。識別不能は欠測。遅延確定結果も元の試験集合へ反映して再判定し、公開後に判明した不合格も停止対象にする。失敗を消すリセットやケース置換は禁止する。

受入開始から60分で必要件数が不足する場合はチームへ通知して公開を保留する。証跡確認・明示再開までは件数が揃っても自動開放しない。100件全成功でも運用の真の成功率99.5%以上の統計的証明とは扱わない。通常負荷試験の20仮想利用者・各操作200試行・定常30分は別の目的として維持する。

## 切替と利用再開

1. 変更記録に対象・成果物・DB変更・切り戻し・予定停止窓を固定し、担当者と別担当確認者を記録する。停止時間は入口閉鎖、処理分類、旧主体排除、実環境試験、再開判断を積算し、許容時間と実施時間帯を別途確定する。
2. 更新時は通常操作の入口を閉じ、本文なし案内、状態確認、ログアウト、独立した権利請求受付等の既存例外を維持する。開始済み処理・未確定試行・停止前引渡し済みデータを既存D-01等の条件で分類する。
3. ゲート更新時は旧版の新規送信・新規本文返却・既存接続・旧URL・資格・全実行者について遮断証拠を照合する。不明・証拠不足ならPendingで新版を閉じる。通常アプリ更新も旧経路から安全条件を迂回できないことを確認する。
4. 実利用を閉じたまま承認済み新版へ一括切替する。実環境の認証・認可・DB・安全台帳・監視経路を確認し、6 APIの正常動作と拒否系、AI・PDFの正常経路を合成データで確認する。ゲートを更新した場合は送信・返却・旧経路拒否も確認する。公開前試験と環境・設定が異なる部分は再検証し、未確認なら開放しない。これらは600件・20試行とは別の追加確認・費用として計上する。
5. 最新の削除・同意・資格状態、二地域保護、未知試行の照合、必要な受入結果と別担当確認が揃った場合のみ新版を全利用者へ一括開放する。権利請求の停止中受信と新着差分も照合する。安全条件不明なら停止継続と未達を報告する。

予定停止時間の上限は未決定で、無期限の計画停止を承認したものではない。段階配備との方式上の矛盾は解消したが、PG-01〜03の実構成成立、PG-04の停止所要時間・再開証拠の実証は未解消。

## 公開後の集中監視・異常停止

開放完了を確認した時刻から最低15分を集中監視する。これは3段階の昇格待ちではなく、一括開放後の確認時間であり、終了後も定常監視を継続する。毎分報告し、0件も0件と報告する。予定時刻から2分以内に報告がない、版・API・合成／実利用を識別できない、必要な結果・時刻記録がない場合は欠測として停止する。定常の実AI監視間隔は変更しない。

新版API別に合成／実利用を分け、開放後累積の確定100件以上から毎分、成功率99.5%以上・p95 2秒以内を判定する。直近5分100件以上の同じ集計窓も併用し、どちらかが基準外なら自動停止。少人数で実利用100件に届かない場合は未判定と表示し、件数を得るために利用者を待たせたり試験成功と見なしたりしない。公開前受入・実環境確認・15分監視が揃い、未確定／遅延結果と安全状態を別担当が確認したら切替完了とする。公開後の実利用件数不足による60分の昇格保留は廃止する。

越権、削除後利用、二重更新、AI/PDF期限制御違反、安全台帳不整合、監視欠測は件数や15分を待たず検知時に自動停止し通知する。安全性不明なら本文操作を遮断する。性能異常でも旧版へ無条件復帰せず、DB互換・最新の削除／同意／資格・実行中処理・ゲート排除を確認した場合のみ承認済み旧成果物へ戻す。確認不能なら閉鎖を維持する。

DBは拡張→両版対応→読取切替→旧形式廃止。非互換移行は停止窓と復旧手順を別レビューする。アプリを戻せばDBも戻るとは扱わず、削除・撤回の復活や全履歴上書きを禁止する。

配備ID、成果物・設定版、公開前／切替確認／公開後の区分、版、API・シナリオ、合成／実利用、送信・受付・確定時刻、未確定件数、失敗、成功率、p95、安全違反、欠測、保留・再開・判断者を本文なしで記録する。
