## 公式仕様から確認した制約

1. Cloud Runの最大インスタンス設定は、複数実行者の厳密な排他証拠には使わない。公式仕様は一時的な上限超過を説明している。[最大インスタンスの制約](https://docs.cloud.google.com/run/docs/configuring/max-instances-limits)。
2. IAM変更は即時の失効保証ではない。旧資格削除のAPI成功を旧実行者の作用不能へ読み替えない。[IAM変更伝播](https://docs.cloud.google.com/iam/docs/access-change-propagation)。
3. ファイアウォールの拒否変更は、接続追跡中の既存接続が残る点に注意が必要。既存接続を含む最終作用の遮断証拠として単独使用しない。[公式firewall仕様](https://docs.cloud.google.com/firewall/docs/firewalls)。
4. Cloud Runの応答タイムアウトはコンテナ終了を意味しない。[公式timeout仕様](https://docs.cloud.google.com/run/docs/configuring/request-timeout)。

結論は「これらの設定を組み合わせれば解決」ではない。最終ゲートを増やしても、最後の許可確認と実引渡しの間に旧処理が停止・復帰する問題は残る。特に停止要求を届けられない旧処理の新規送出を、この案で禁止できるとの証拠はまだない。Pending表示もその証拠にはならない。

## 配置候補

検証環境とβは分離。以下は各環境内の仮名称で、総プロジェクト数は既存6という数字を固定せず、業務・制御・復旧の独立性を確認して費用と一緒に更新する。安全台帳の耐久保護先は東京T／大阪Oのみ。

| 主体 | 配置・資格候補 | 許す役割 | 禁止する役割 |
| --- | --- | --- | --- |
| entry-return | 東京主系・大阪待機の専用Cloud Run、return-sa | 患者本人の認証・最終本文返却・本文なし状態案内。業務要求をbusinessへ渡す | 任意外部AI送信、権限変更、任意DB操作、直接の別返却経路 |
| business | Cloud Run、business-sa | ドメイン処理、許可されたwriter操作と最終送信要求を依頼 | 患者本文を直接返す公開入口、外部AI資格、本文DB直接書込み、任意外向き通信 |
| business-writer | 内部Cloud Run、writer-sa | 業務DBの禁止文書を読み通常書込みと同一トランザクションで検証 | 外部AI、患者への直接本文返却、勝手な禁止解除 |
| safety-coordinator | 本文を持たないCloud Run、safety-sa | T/O台帳、停止意図・照合・業務DBへの禁止適用要求 | 医療本文の取得、送信、一般利用者への公開 |
| final-send | 専用Cloud Run、send-sa | 許可された最小入力の外部送信、試行の分類 | 任意URL・リダイレクト追従、資格管理、一般公開 |
| PDF-worker | 内部Cloud Run、pdf-sa | 確認済み版のPDF生成、短期保存、ゲートへの結果参照返却 | 任意外部URL取得、無認証の署名URLでの患者直接配信 |
| deploy/recovery | 通常運営と分離する短期資格 | 承認版の配備、隔離復元、証拠収集 | 一般業務資格での自己再開・自己権限拡張 |

本文は保護された参照・必要最小限の入力で受け渡し、制御台帳へ複製しない。entry-returnは患者本文を返す最終実行者なので、final-sendと同じ停止・世代管理の対象とする。「業務側の応答」を無検査でそのまま返却しない。PDF配信も最終返却の認可を通し、旧URLによる迂回を作らない。

return-sa等のAPI到達権は利用者のデータ認可を代替しない。対象・本人・目的・同意・世代の検証を内部操作にも要求する。FirestoreサーバーSDKはSecurity Rulesを迂回するため、Rulesだけでwriterの操作範囲を守ったとはしない。IAMのDB境界とRepositoryの業務認可を対応付け、コレクション単位の分離を未確認のIAM機能へ依存させない。[Firestoreサーバー認証](https://docs.cloud.google.com/firestore/native/docs/security/get-started)。

## 通信と迂回拒否

外部入口はロードバランサー経由のentry-returnと本文なしの独立受付・案内に限定する候補。business／writer／final-send／coordinator／PDFは内部到達とサービス別invoke権を併用する。Cloud Run間の呼出しは対象を固定したID tokenと、宛先サービスに限定したInvoker権を候補とする。[サービス間認証](https://docs.cloud.google.com/run/docs/authenticating/service-to-service)。

デフォルトrun.app URL、タグURL、旧revision、カスタムドメイン、直アクセス可能な内部サービス、Storage URLを一覧化して試す。入口に応じてdefault URL無効化等を検討し、内部呼出しへ必要なURLまで無効化しない。HostヘッダーやURLが非公開というだけで認証済みとしない。[Cloud Run ingress](https://docs.cloud.google.com/run/docs/securing/ingress)。

businessとwriterはDirect VPC egressのall-trafficを候補に、宛先制限を適用する。内部Cloud Run、必要なGoogle API、DNS等を機能単位で許可する。ただしGoogle API一般や共有IPへの広い許可を患者情報の搬出防止と同一視しない。プロキシ・任意URL受付・redirect・任意Cloud Storage等を経由できないかも試す。最終sendだけが必要な宛先と秘密へアクセスする。NATはアドレス変換であり、それ自体は宛先許可リストでも即時停止フェンスでもない。[Direct VPC egress](https://docs.cloud.google.com/run/docs/configuring/vpc-direct-vpc)、[内部通信経路](https://docs.cloud.google.com/run/docs/securing/private-networking)。

管理主体は署名済みダイジェスト・サービスID・設定版を照合し、通常サービスへ他のSAの偽装やdeploy権を付与しない。通常業務の直接DB資格も外す。許可した最終ゲートを介した不正な対象取得も拒否試験へ含める。

## 停止・旧実行者・再開の状態

| 状態 | 条件と扱い |
| --- | --- |
| Open | 対象世代・環境世代・二地域保護と必要な実行経路が確認できる範囲のみ作用許可 |
| StopRequested | 停止意図を最終経路へ通知、新規要求を拒否。未到達の旧実行者の動作まで保証したとはしない |
| Quiescing/Pending | 台帳照合・業務禁止更新・作用一覧・旧実行経路を確認。不明試行・未確認の実行者が残れば確認完了へ進めない |
| Blocked | 必要な業務禁止、二地域記録、対象に作用可能な全経路の停止証拠を確認できた場合のみ記録。モデルのbooleanを証拠にしない |
| Accepted | 既存受付契約に従う独立確定。物理消去完了とは区別し、元の期限を維持 |
| ReopenReview | 対象分離、耐久受信照合と新着差分、旧世代拒否、別担当確認、二地域保護をそろえて開放判断 |

必要な証拠は実行者一覧の完全性、対象・世代・試行と最終引渡しの対応、停止確認応答の元、既存接続・未確定試行の扱い、旧資格・旧入口の拒否試験、再開承認者。アプリが停止確認を返しただけでは実行者一覧の完全性を証明しない。

全実行者の把握・厳密な排他をCloud Runのmax1だけで実現する案は不採用。単一所有者・世代・登録台帳を検討する場合も、所有者交代後に旧プロセスが送れない最終フェンスが必要であり、DB上の世代更新だけでは不足。全経路の作用不能が説明できない場合は候補不成立のまま保持する。
