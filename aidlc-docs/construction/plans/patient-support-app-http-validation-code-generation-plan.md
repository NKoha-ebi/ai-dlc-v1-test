## 対象と配置

既存experiments/patient-support-safety/へ追加し、固定依存と既存26試験を保持する。Node.js組込みのhttp・child_processを使い、新しいnpm依存は原則不要。既存患者アプリ、ルート依存、クラウド、実AI・実メールには接続しない。

親テストと子プロセスは127.0.0.1のOS割当ポートとIPCのみ使用。子プロセスへ渡す環境変数は必要な実行環境項目に限定し、秘密情報を収集しない。listenerが別インターフェースをbindしないことを確認する。全子プロセス・接続・一時ファイルは試験のfinallyで解放する。

ソースはsrc/http-validation/、試験はtests/http-validation.test.ts、結果資料はaidlc-docs/construction/patient-support-app/code/http-validation-summary.md。前回モデルと同じU01のUS-12・15・19およびUS-04・13の安全境界を対象とし、各ストーリー全体の完成とはしない。

## インターフェース

IPCメッセージは対象ID・試行ID・世代・種別・checkpoint・連番・制御状態を持ち、各要求へ対応する応答を照合する。模擬受信先はfirst-body、body-complete、response-sentを記録する。送信側は予約・直前確認・write・finish・停止受信・停止確認・接続終了を記録する。

checkpointで待機／解除して競合を注入する。Windowsで未対応のSIGSTOPに依存せず、明示的なIPC待機と子プロセス終了を使う。これはOSやランタイムを任意のCPU命令で停止させる検証ではなく、その範囲は報告に残す。

停止済みの証拠が欠ける場合はPending、応答がないときは試験自体を期限付きで終了し、停止成功には数えない。計測上の待機上限はハーネスの終了条件であり、本製品の停止保証時間にはしない。

## 固定シナリオ

| ID | 操作・故障 | 必要な観測・判定 |
| --- | --- | --- |
| H-01 | 予約後に送信要求を待機、停止処理後に再開 | 新規本文送信なし、受信先本文0。予約のみで開始済みと判定しない |
| H-02 | 最終許可確認前に停止、その後確認を再開 | 拒否。ヘッダーだけで本文送信済みとはしない |
| H-03 | 許可確認後・実write直前に停止を挿入 | 古い確認を使い回す欠陥対照を検出。候補方式で順序を処理できなければ不合格／未成立を記録 |
| H-04 | 最初の本文受信後に停止 | 同じ試行の残りだけ完了可。新規再送・結果保存・新たな返却を拒否 |
| H-05 | 本文送信後に受信先の応答を喪失 | 成否不明を保持し、自動再送しない。finishと受信イベントを別記 |
| H-06 | 旧送信子プロセスをcheckpoint待機後、停止して復帰 | 拒否。停止確認を返せないcheckpointではPendingを維持。証拠なしで代替実行者を開放しない |
| H-07 | 送信プロセスを終了、受信側記録と照合 | 対象プロセス終了は確認するが、OSへ渡した情報の回収証拠にはしない。未確認試行は保留 |
| H-08 | 一括結果がそろう前／返却直前に停止 | AI結果本文を新規返却しない。開始済み返却の残りの例外と区別 |
| H-09 | 対象停止中に通常操作・最小状態確認を要求 | 通常操作と患者本文を拒否、必要最小限の状態応答のみ許可。実認証の実装・証明は今回の対象外 |

本文chunk受信時刻だけで新規送出時刻を推定しない。全イベントの順序と試行分類を照合して判定し、証拠不足はunknownとして結果を残す。相手に到達した情報を取消したとの主張をしない。
