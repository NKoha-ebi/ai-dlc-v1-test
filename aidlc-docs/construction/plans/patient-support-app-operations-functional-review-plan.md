# U01 運営者機能の再確認計画

## 目的と状態

2026-11-02のユーザー指示に基づき、非機能要件を中断し機能設計を再開する。従来の承認は履歴として保持し、運営者機能を見直した修正版は再承認を必要とする。

## 進行

- [x] 現行の運営画面・操作記録・責務境界と進捗を確認する。
- [x] 非機能要件の中断と機能設計への差戻しを状態・質問・監査へ記録する。
- [x] 既存の運営機能一覧と不足事項を整理し、確認質問を作成する。
- [ ] ログの記録対象、閲覧できる担当者、検索条件、表示項目、患者との紐付け、書出し可否を確認する。
- [ ] アカウント・権限、コンテンツ、問い合わせ、公開制御、内部集計の運営フローと例外を点検する。
- [ ] 回答に基づき要件・ストーリー・画面・契約・業務規則・データモデルを整合する。
- [ ] 修正版を検証し、標準の修正依頼／次段階へ進むの2択で承認を受ける。

## 確認した境界

レビュー資料：[運営機能・画面案](../patient-support-app/functional-design/operations-functional-review-proposal.md)を先に読み、[21問の確認質問](patient-support-app-operations-functional-review-questions.md)へ回答する。質問数・回答欄各21、相対リンクを検証済み。現在は回答待ち。

操作記録の保存と運営者の閲覧機能は別であり、専用ログ画面・閲覧権限は未定義。US-19は開発運用の変更記録で、患者操作ログ閲覧機能の承認根拠とはしない。運営権限だけで患者整理本文を取得しない既存制約を維持する。記録するイベントと業務上の閲覧要件は機能設計で整理し、保存基盤・性能・監視方式は後続設計へ渡す。

この計画は新しいログ閲覧・書出し機能の採用決定ではない。既存の患者画面・配色・同意・削除条件、拡張設定、研究実データ無効の条件は維持する。
