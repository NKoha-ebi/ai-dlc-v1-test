# アプリケーション設計計画

## 前提

実行計画の回答Aと「承認しました」を受領。ユーザーストーリー23件・ペルソナ・FR-01〜14／NFR-01〜08を入力とする。既存Reactひな形の構成は参考とし、言語・フレームワークは非機能要件・設計で選定する。詳細UIは機能設計とコード生成で具体化し、本段階では画面の役割・関係を扱う。

## 設計方針案

患者画面と権限別の管理者用Web画面、サーバー側の業務処理、共通の永続保存を論理的に分離する。サーバーは認証・権限・同意、患者整理、AI連携、PDF、運営、研究・集計を責務別に整理する。初期版では1つのバックエンド内でモジュールを分ける構成を推奨し、別サービスとしての個別配備は必要性が判明してから検討する。物理DB構成・配備方式・製品はここでは確定しない。
