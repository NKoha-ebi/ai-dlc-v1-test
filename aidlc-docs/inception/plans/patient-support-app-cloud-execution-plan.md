## 工程と依存

- [x] 既存アプリ、クラウド接続要件、独立受入条件を照合。
- [x] 構築範囲と工程を整理。
- [x] 実行計画を承認。
- [ ] アプリケーション設計と作業単位を定義。既存 React 画面を使い、Vite から切り出すサーバー入口、Firebase Authentication／専用 Firestore、OpenAI アダプター、配備資材の責任範囲を定める。
- [ ] 機能・非機能・インフラを設計。本人認証、同意、保存と再試行、退会と削除、注意事項の選別、API 異常時の復帰を具体化。Cloud Run、Secret Manager、テスター認証、HTTPS ロードバランサー、費用・容量・監視・停止を設計する。
- [ ] コード生成。認証・保存の契約を決めた後に OpenAI を接続し、配備前にローカルで統合確認。
- [ ] ビルドとテスト。イメージを作成し、限定配備で CV-01〜07 とリビジョン復帰を確認。

工程は計画承認 → アプリケーション設計・作業分解 → 機能・非機能・インフラ設計 → 実装 → ビルド・限定配備・受入の順とする。

認証、外部 API、永続化、入口に影響する。アプリ専用 DB と既存の安全台帳は分離し、配備前に誤公開と費用増加への対策を評価する。所要時間は認証、秘密の登録、入口方式の確定後に見積もる。追加の全体リバースエンジニアリングは既存資料の再利用により省略。Operations はプレースホルダー。

RESILIENCY-03 は承認記録に反映。04・05・06・09・10 は後続で設定と証拠を確認。その他の回復力規則はこの計画差分の対象外。部分 PBT はコード生成前のため対象外。無効セキュリティ拡張は適用省略。
