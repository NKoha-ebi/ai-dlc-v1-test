# コンポーネント設計

設計レビュー用。単一バックエンド内の責務別モジュール構成。論理境界であり個別サービス配備を要求しない。共通DBでもモジュール別の保存インターフェースを通し、画面から直接DBへ接続しない。

| ID・コンポーネント | 責務・公開インターフェース | 重要度・停止影響 |
| --- | --- | --- |
| C01 患者Web | 登録、同意、疾患情報、5支援、再開、PDF、評価、削除、問い合わせ、記事。本人用APIを呼ぶ | 高。相談準備が停止 |
| C02 管理者Web | 運営と研究を権限別に表示。運営用APIと研究用APIを区別 | 中。管理・研究が遅延。公開制御操作への影響は高 |
| C03 認証・認可 | メール認証、アカウント利用状態、役割に基づく認可。業務固有判定を集中させない | 高。全認証操作が停止 |
| C04 同意管理 | 未成年同意・研究同意と撤回の正本、同意条件の判定を管理 | 高。同意依存操作を許可できない |
| C05 患者整理 | 疾患情報、自由記述、5支援、明示ルール候補の採用、患者本人による内容確認、確認済み版、戻る、下書き・履歴を管理 | 高。入力・整理・再開が停止 |
| C06 AI接続 | 許可された抽出・構造化を外部AIに依頼し、型と処理状態を検証。未確認のAI案を返し、整理内容を直接確定しない | 高。AI利用操作が停止。既存結果の閲覧は独立 |
| C07 PDF | C05の確認済み版に対応するスナップショットからPDF生成 | 高。診察準備が遅延 |
| C08 評価 | 完了整理の最新1評価、件数・平均点を提供 | 中。評価・集計が遅延 |
| C09 個人データ管理 | 本人データ管理・退会に伴う削除の進行・結果・失敗・再試行・完了を調整・追跡 | 高。管理・削除が停止 |
| C10 運営管理 | アカウント停止・解除、研究者権限設定。患者整理内容の閲覧権限は付与しない | 中。管理が遅延 |
| C11 公開コンテンツ | お知らせと情報提供記事を別種別で管理。下書き・公開状態、公開一覧・詳細を提供 | 中。情報提供が停止 |
| C12 ページ公開制御 | 対象ページと関連APIの公開制御・利用可否、メンテナンス案内、運営の解除経路を管理 | 高。誤停止・解除不能が利用全体へ波及 |
| C13 問い合わせ | 本人の送信・履歴・確定返信閲覧、運営の一覧・状態・自由記述返信管理 | 中。問い合わせ対応が遅延 |
| C14 研究・提供集計 | 研究条件の承認状態・許可範囲を管理し、C04の同意と権限を確認して識別情報除去済み閲覧・許可集計を提供 | 中。研究・報告が遅延 |
| C15 永続保存 | 所有モジュール別の保存実装、更新結果と版、整合性の保存境界 | 高。保存と再開が停止 |
| C16 操作記録・稼働観測 | 実施者・対象・変更・結果・日時、主要操作成功失敗を記録。本文の無条件転記を避ける | 高。変更追跡・障害検知が不十分になる |

配備候補は患者Web（高）、管理者Web（公開制御を含むため高）、単一バックエンド（高）、共通永続保存（高）。観測先を独立配備する場合は高として後続設計で対応付ける。外部AI（高）は自組織の配備単位ではないが依存障害として測定する。物理的な配備先・製品は未選定。

保護者は同意関係者であり患者内容の閲覧者ではない。製薬会社は許可集計の提供先で、専用アカウント・画面は追加しない。研究者のみの権限では問い合わせ・運営コンテンツの管理を許可しない。

## 判定・データ管理の境界

C03は認証・アカウント利用状態・役割、C04は同意・撤回、各データ所有モジュールは所有者・業務状態、C12は対象画面・関連APIの公開制御、C14は研究条件・許可範囲を判定する。アプリケーションサービスが操作に必要な判定だけを組み合わせる。事前判定は所有モジュールの制約維持を代替しない。必要情報を確認できない操作を許可済みと扱わない。

各業務モジュールがデータと業務制約を管理し、C15は保存実装を担う。他モジュールからの利用は所有元が許可する公開・参照契約を通す。共通DBや管理されたProjection参照は許容するが、Repository・テーブルの直接利用で制約を迂回しない。C14は同意の独立正本を持たない。研究閲覧・製薬会社向け提供にはC14の判定を必須とし、C08の内部集計とは区別する。

確認済み版の固定・履歴保持は、患者の後からの内容修正を禁止しない。C05が修正後の版と再確認を管理する。C09が削除を調整し、各所有モジュールが自身のデータを処理する。同意撤回は削除と別の操作であり、撤回方針に沿って利用制限を反映する。遅延AI結果や派生データの再保存で削除済みデータを復活させない。

公開停止・アカウント停止・同意による制限を区別する。運営の解除経路は通常の停止対象から分離し、認証・権限確認を必須とする。C12自体の障害からの復旧可能性は後続設計の要求とし、具体手段は未確定。

AI・PDF失敗を下書き保存や保存済み閲覧へ不要に波及させない。単一バックエンドでは全障害の完全分離を保証しない。C16の監査・操作記録と稼働観測は目的・データを論理的に分離し、別配備は要求しない。
## 運営用当月集計の追加差分（US-28）

C02は運営用O06を追加し、外部提供用O05と区別する。C10は運営用集計取得の入口を担当し、患者本文閲覧権限を追加しない。C05は利用・初回完了記録、C08は最新評価・集計の所有元とする。所有元の保存契約を通して必要項目を集約し、元患者データ・評価の複製、専用DB、独立サービスを必須にしない。
