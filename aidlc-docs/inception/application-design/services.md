# サービスと処理調整

サービスは単一バックエンド内のアプリケーション層。専用の別サービス配備や新しい通信基盤を確定しない。

| サービス | 調整する責務 | 処理順と失敗時の方針 |
| --- | --- | --- |
| 利用開始 | C03・C04・C05 | 認証、対象年齢・必要同意、本人プロフィール。保護者同意で閲覧権限を追加しない |
| 患者整理 | C03・C04・C12・C05・C06・C15 | 操作可否、入力保存、明示ルール選択、必要時AI、未確認案保存、本人確認。AI失敗でも既存入力を保持 |
| 再開・修正 | C03・C12・C05・C15 | 保存状態取得、未送信との突合、承諾後の修正、関連生成結果の更新と再確認。競合方式は後続承認 |
| PDF取得 | C03・C12・C05・C07 | 本人の確認済みスナップショットを取得して生成。新たなAI呼出しへ依存しない |
| 評価 | C03・C08・C15 | 完了整理の所有者を確認し最新評価を保存。集計への重複計上を防止 |
| 削除・退会 | C03・C04・C09・各所有モジュール | 対象特定、削除受付、関連データ処理、結果追跡。研究撤回・バックアップ復元後の再削除も後続設計対象 |
| 運営 | C03・C10・C15・C16 | 運営権限確認、状態・権限更新、操作記録。患者整理の本文を返さない |
| コンテンツ提供 | C03・C11・C12・C15・C16 | 運営編集と公開変更を記録。患者取得はページ利用可否と公開状態の両方を確認 |
| メンテナンス | C03・C12・C15・C16 | 運営確認、公開切替、変更前後を記録。解除経路を通常ページ停止から分離。進行中操作は機能設計で具体化 |
| 問い合わせ対応 | C03・C12・C13・C15・C16 | 本人送信、運営対応・返信下書き、返信確定、患者本人閲覧。下書きは返さず失敗を確定済み扱いしない |
| 研究閲覧 | C03・C04・C14・C15 | 有効化条件、研究権限、各対象の同意、承認範囲、識別情報除去、取得。条件未承認なら実データを拒否 |
| 提供集計 | C03・C04・C08・C14 | 承認条件、期間別の許可3指標、対象人数・差分推定抑制、運営確認。製薬会社専用画面・CSV出力は追加しない |

全サービスでContextをサーバー側で確立し、直接APIでも認可を実施する。状態変更と操作記録の整合性、再送・タイムアウト・処理途中失敗の回復は機能設計・NFR設計へ引き継ぐ。US-19の変更承認・復旧手順は開発運用上の記録であり専用業務画面ではない。
