# サービスと処理調整

サービスは単一バックエンド内のアプリケーション層。専用の別サービス配備や新しい通信基盤を確定しない。

| サービス | 調整する責務 | 処理順と失敗時の方針 |
| --- | --- | --- |
| 利用開始 | C03・C04・C05 | 認証、対象年齢・必要同意、本人プロフィール。保護者同意で閲覧権限を追加しない |
| 患者整理 | C03・C04・C12・C05・C06・C15 | 操作可否、入力保存、明示ルール選択、必要時AI、未確認案保存、患者本人による内容確認。AI失敗でも既存入力を保持 |
| 再開・修正 | C03・C12・C05・C15 | 保存状態取得、未送信との突合、承諾後の修正、関連生成結果の更新と再確認。競合方式は後続承認 |
| PDF取得 | C03・C12・C05・C07 | C05の許可された契約で所有者・確認状態・版対応を満たすスナップショットを取得して生成。新たなAI呼出しへ依存しない |
| 評価 | C03・C05・C08・C15 | C05の契約で所有者・完了状態等を確認しC08が最新評価を保存。集計への重複計上を防止 |
| 削除・退会 | C03・C04・C09・各所有モジュール | 対象特定、削除受付、関連データ処理、結果追跡。研究撤回・バックアップ復元後の再削除も後続設計対象 |
| 運営 | C03・C10・C15・C16 | 運営権限確認、状態・権限更新、操作記録。患者整理の本文を返さない |
| コンテンツ提供 | C03・C11・C12・C15・C16 | 運営編集と公開変更を記録。患者取得はページ利用可否と公開状態の両方を確認 |
| メンテナンス | C03・C12・C15・C16 | 運営確認、公開切替、変更前後を記録。解除経路を通常ページ停止から分離。進行中操作は機能設計で具体化 |
| 問い合わせ対応 | C03・C12・C13・C15・C16 | 本人送信、運営対応・返信下書き、返信確定、患者本人閲覧。下書きは返さず失敗を確定済み扱いしない |
| 研究閲覧 | C03・C04・C14・許可された参照元・C15 | 有効化条件、研究権限、各対象の同意、承認範囲、識別情報除去、取得。条件未承認なら実データを拒否 |
| 提供集計 | C03・C04・C14・各指標の所有元（C08等） | 承認条件、期間別の許可3指標、対象人数・差分推定抑制、運営確認。製薬会社専用画面・CSV出力は追加しない |

登録・ログインはContext確立前の認証入口として扱い、認証後の業務操作ではContextをサーバー側で確立する。直接APIでも必要な条件を検証する。状態変更と操作記録の整合性、再送・タイムアウト・処理途中失敗の回復は機能設計・NFR設計へ引き継ぐ。US-19の変更承認・復旧手順は開発運用上の記録であり専用業務画面ではない。

## 判定分担と操作の調整

C03は認証・利用状態・役割、C04は同意・撤回、所有元は所有者・業務状態、C12は対象画面・関連APIの公開制御、C14は研究条件の承認状態・許可範囲を担う。サービスは操作に必要な判定だけを組み合わせ、所有モジュールも自身の制約を維持する。必要情報を確認できなければ条件充足としない。表の責務列は主な調整先であり、この共通分担も合わせて適用する。

患者整理では入力版に対応する未確認案、生成完了、保存結果、患者による内容確認、確認済み版を区別する。一回の同期処理として固定しない。通常再開は下書き・保存状態の回復であり戻る修正ではない。戻る取消時は入力・結果を保持して再生成しない。承諾後に入力を修正した場合はFR-08・US-11どおり関連生成結果を再作成し患者本人が再確認する。再生成を省略できる追加条件は設けない。

PDF用内容はC05の公開契約を通す。サービスが取得するかC07が取得するかは固定しない。PDFは新しいAI生成に依存せず、失敗で入力・確認済み保存を失わせない。評価サービスはC05へ所有者・完了状態等を確認するが整理本文を取得せず、1〜10・最新値置換・0回答の算出不能等の評価制約はC08が維持する。

削除・退会はサービスがユースケース全体、C09が削除の調整・追跡、各所有元がデータ処理を担う。同意撤回はC04の正本更新を起点とする別操作で、C14と派生データ所有元へ必要な利用制限を反映する。削除後に遅延AI結果・派生データが元データを復活させない。

C10の研究者権限設定とC14への承認済み研究条件の反映は別であり、運営に新しい研究承認権限を与えない。研究閲覧の検索・個別取得はともにC03の権限、C04の同意、C14の承認条件・許可範囲と許可された参照元の制約を満たす。識別情報除去・範囲制限を適用した結果だけを研究者へ返す。

提供集計はC14の条件確認・抑制を必須とする。運営確認やC08の集計だけでは許可しない。利用件数・完了件数・整理実感スコアの所有元と参照経路は依存資料を参照し、全指標をC08から取得する構成に固定しない。

表中のC15は所有モジュールを介した保存依存であり、サービスが他モジュールの保存領域を直接操作する意味ではない。AI失敗時の入力保持、解除経路の通常停止対象からの分離と認証・権限確認、返信下書きの患者への非開示を維持する。C12自体の障害時の復旧は非機能・インフラ設計へ引き継ぐ。
