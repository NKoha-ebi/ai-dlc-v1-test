# 依存関係・通信・データフロー

表の矢印は呼出元から依存先。行にない無条件の横断読取は認めない。

| 呼出元 | 主な依存先 | 通信・データ |
| --- | --- | --- |
| C01 患者Web | C03、患者用サービス、C11〜13 | 認証付き業務API。本人データ・公開記事・本人問い合わせだけを取得 |
| C02 管理者Web | C03、運営サービス、研究サービス | 役割別API。画面表示だけを認可根拠にしない |
| 各業務サービス | C03・C04・C12 | 認証・同意・ページ操作可否。業務上必要な同意条件だけを適用 |
| C05 患者整理 | C06、C15 | モジュール内呼出しと保存。AI依頼は外部I/O |
| C06 AI接続 | 外部AI | 最小限の許可入力と未確認出力。認証情報・問い合わせを渡さない |
| C07 PDF | C05、C15 | 本人確認済み内容の読取。外部AIなし |
| C09 個人データ管理 | C04・C05・C08・C13・C15 | 所有モジュール経由で関連削除。研究側との整合を後続具体化 |
| C10 運営管理 | C03、C15、C16 | アカウント・権限と操作履歴 |
| C11 公開コンテンツ | C15、C16 | お知らせ・記事の下書き・公開版 |
| C12 公開制御 | C15、C16 | ページ・操作の利用状態。案内・解除経路は別扱い |
| C13 問い合わせ | C15、C16 | 問い合わせ・状態・返信下書き・確定返信 |
| C14 研究・集計 | C04、C05・C08の承認Projection、C15 | 目的・同意範囲内の取得。C13への自動連携なし |
| 各更新・主要操作 | C16 | 操作結果・観測。本文を無条件複製しない |
| 各所有モジュール | C15 | 専用Repository。画面・研究者からの直接DBアクセスなし |

ブラウザーと業務APIはHTTPSを前提とする論理設計。単一バックエンド内はメソッド呼出し、永続保存はRepository、AIは接続アダプター経由。イベントバス、キュー、別マイクロサービス、物理DB分割は未選定。

## データフロー（テキスト）

1. 患者入力 → 認証・本人・必要同意・ページ操作判定 → C05保存 → 必要な承認済みAIタスク → 未確認案 → 本人修正・確認 → 確認済み保存 → PDF。
2. 通信断 → ブラウザー側の未送信下書きを保持 → 再接続・再認証 → 保存済み版と照合 → 承認された競合方式で再開。端末保存方式は後続選択。
3. 患者問い合わせ → 本人確認 → C13保存 → 運営権限で一覧・対応 → 自由記述の下書き → 確定 → 問い合わせ所有者がアプリ内閲覧。通知は未決定。
4. 運営の記事／お知らせ → 下書き → 公開確定 → 公開状態とページ可否を確認した一覧・詳細 → 患者。非公開時は直接指定でも本文を取得しない。
5. 研究要求 → 研究条件承認・役割・同意・目的判定 → 許可Projection → 識別情報除去 → 検索・閲覧。集計はさらに人数・差分推定抑制 → 許可指標のみ。条件未承認時は合成データで検証する。
6. 運営のメンテナンス切替 → 認可 → 状態保存・操作記録 → 画面と対象APIに反映 → 案内。運営解除経路から再公開。

## 障害の波及

保存・認証障害は各業務へ波及する。外部AI障害はAI利用操作に波及するが、保存済み閲覧とPDFをAI稼働に結合しない。コンテンツ・問い合わせ障害で患者整理の状態を変更しない。単一バックエンド停止は全サーバー業務へ波及するため配備単位は高重要度。公開制御の取得失敗時の扱い、キャッシュ整合、操作記録障害時の可否はNFR設計で決める。
