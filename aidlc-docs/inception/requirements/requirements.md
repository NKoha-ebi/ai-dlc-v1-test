# 要件定義書（承認待ち）

## 意図分析

患者が希望・困りごとを整理し、医療者への相談に使えるカードを作るアプリ。既存React・TypeScript・Viteのひな形を基に、新規機能をシステム全体へ追加する複雑な開発。実際の患者情報を扱う運用を目指す。認証・サーバー保存・AI接続は未実装。

出典: requirement-verification-questions.md の19回答、requirements-clarification-questions.md の9回答、requirements-analysis-notes.md。補足確認3項目の回答も反映。補足質問4Aにより、RTO・RPOはいずれも10分と確認済み。未承認の提案を確定事項として扱わない。

## 機能要件

- FR-01: 対象は15〜39歳。患者はスマートフォン、運営・研究利用はPC対応。15〜17歳は本人と保護者等の同意確認を行い、保護者の内容閲覧権限は自動付与しない。確認方法・文面・必要なレビューは設計で具体化する。
- FR-02: メールアドレスとパスワードで登録・認証し、本人の入力・対話・カードは本人が閲覧・編集・削除できる。研究アクセスはFR-11の同意・権限で分離する。
- FR-03: がん種は広い分類と「その他・不明・回答しない」。治療時期は「治療前・治療中・治療後・経過観察・その他・不明・回答しない」。治療中は「手術・抗がん剤治療・ホルモン療法・化学放射線治療・放射線治療・その他・不明・回答しない」を複数選択する。治療内容の回答は必須。「回答しない」の明示選択と未入力を区別する。
- FR-04: 独立した5支援モジュールを設ける。価値観の整理、やりたいことの明確化、疾患・治療に関する懸念点の整理、実現プランの検討、医療者への確認事項の整理。順序変更・省略・再実行が可能。価値観の整理は必須の前段階としない。
- FR-05: 生成AIが自由記述を抽出・構造化し、本人が確認・修正する。明示的ルールで支援候補を提示し、候補が複数なら本人が選択する。各モジュールのAI利用範囲・遷移条件・行動案生成・回数上限は機能設計で検証案を提示し承認後に実装する。
- FR-06: 医学的な実行可否、治療変更、検査値の医学的判断を確定しない。医療者に確認する事項として残す。画像入力・OCR・イラスト生成は対象外。
- FR-07: 通常中断・通信断でも下書きを保持し、再接続後に再開する。未送信データとサーバー保存済みデータを区別する。保持方式・競合処理は設計で決める。
- FR-08: 1つ前に戻る前に確認し、承諾後に入力を保持して修正する。関連する生成結果を再作成し本人が再確認する。取消時は再生成しない。不要なAPI利用を抑える。
- FR-09: 本人確認済みの「やりたいこと・困りごと・選んだ行動案・医療者への質問・作成日」を基本1ページのPDFとしてダウンロードできる。氏名・画像は載せず、本人が提示する。
- FR-10: 本人が削除するまで保存し、退会時は関連データも削除対象とする。削除期限とバックアップ、研究データ・同意撤回との整合は設計に引き継ぐ。研究側の撤回方針は要確認。
- FR-11: 初期版に運営画面、研究画面、製薬会社向け集計を含める。明示的な研究参加同意を前提に、研究者が識別情報を除いた個別データを扱う。製薬会社には個人を識別しない集計のみ提供する。運営はアカウント状態確認・利用停止／解除・研究者権限管理。研究者は同意済みデータの検索・閲覧のみとし、個別データの書出しは行わない。製薬会社向けは期間別の利用件数・完了件数・整理実感スコアのみ。対象10人未満の集計および差分から推定可能な集計は表示しない。研究主体・目的・対象データ・権限・撤回後の扱いと同意文面を確認し承認するまで、実データへの研究アクセスと製薬会社への提供を無効にする。識別情報の除去だけで匿名性が保証されるとは扱わない。
- FR-12: 完了した整理1件につき1〜10点で評価し、再回答は最新値で置換する。「整理実感スコア」は平均点×10、目標80以上。未回答・途中離脱は別集計。回答0件は算出不能と表示する。集計期間は設計で具体化する。

## 非機能要件と運用

- NFR-01: 日本語、スマートフォン対応、キーボード操作、可読性、処理中表示、再試行を備える。
- NFR-02: 本人認証・役割によるアクセス制御と研究同意の境界を維持する。セキュリティ拡張の無効化はこれらの明示要件を削除しない。
- NFR-03: 同時利用人数・応答時間・AI利用先・費用上限・保存地域・削除期限は後続設計で提案し、承認を得る。
- NFR-04: 災害復旧方針は最小構成の待機環境（Pilot Light）。補足質問4Aにより、初期版の患者・運営・研究・集計の各機能に共通してRTOは障害から10分以内、それらの永続データのRPOは最大10分とする。一定期間のベータ試用でも使いやすさを確保し、利用中断と保存済み入力のやり直しを抑えるための目標。未送信下書きの保持要件は別途維持する。目標は実測済みの保証ではなく、Pilot Lightでの達成可能性・費用を非機能設計と復旧試験で検証し、達成できない場合は承認を得て構成または目標を見直す。
- NFR-05: 可用性の初期提案は月間99.5%、24時間を対象とする。患者向けの認証・整理・保存・PDFと運営・研究画面の主要操作を対象に、各操作の成功可否を独立して測定し、一部機能の障害を全体平均で隠さない。AIが必要な整理操作ではAI障害も失敗に含める。計画停止も停止時間に含め、外部からの定期確認とリクエストの成功記録を用いて測定する。30日換算の停止許容は216分。一定期間のベータ試用と費用の両立のための初期提案であり、診察前の利用を保証する値ではない。RTOの10分とは単一障害時の復旧目標として区別する。対象・測定間隔・成功条件の詳細は非機能設計で具体化する。数値は要件承認まで未確定。
- NFR-06: 本番変更は変更記録、承認、切り戻しメモを含む簡潔な手順を提案する。変更ごとに目的・影響・検証結果・実施者・承認者・復旧条件を記録し、実施後の確認を残す。具体的なツールは後続設計。
- NFR-07: 純粋関数と保存形式の往復にPBTを部分適用する。PBT-02・03・07・08・09を必須とし、その他は助言。フレームワーク選定とテスト生成は後続段階。
- NFR-08: CI/CD・切り戻し方式・リリース方式・地域構成・障害対応・復旧試験は非機能設計でユーザーが選択する。未選択の方式を確定しない。

## 検証観点

本人以外からのアクセス拒否、研究同意の有無によるアクセス分離、保護者への自動開示防止、通信断からの再開、戻る操作の取消時のAPI未呼出し、本人によるAI結果の確認、PDF掲載項目、評価の最新値置換を受入検証へ引き継ぐ。運営の許可操作と権限外操作の拒否、研究利用無効時のサーバー側アクセス拒否、個別データ書出し禁止、9人以下の集計抑制、10人以上でも差分推定可能な集計の抑制を検証する。

## 論理機能の重要度・影響・依存関係

| 機能                       | 重要度 | 停止時の影響                                             | 依存関係                                                                           |
| -------------------------- | ------ | -------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 認証・同意・アクセス制御   | 高     | ログインと権限確認ができず、患者・運営・研究の操作が停止 | 画面から認証・同意管理、永続保存へ依存。全機能が利用                               |
| 患者の整理・下書き保存     | 高     | 診察前の準備が中断し、保存不備で入力を失う可能性         | 認証・保存・ルール処理へ依存。AI使用箇所は外部AIにも依存                           |
| AI処理                     | 高     | 抽出・構造化や下書き生成が停止                           | 患者整理から呼出し。外部AIへ依存。障害時も既存データの閲覧を維持する設計へ引き継ぐ |
| PDF作成                    | 高     | 医療者への提示準備が遅れる                               | 認証・本人確認済みの保存データへ依存                                               |
| 運営管理                   | 中     | アカウント管理・利用停止・権限付与が遅れる               | 認証・権限・アカウント状態の保存へ依存                                             |
| 研究閲覧・製薬会社向け集計 | 中     | 研究・報告が遅れる。条件承認までは実データ利用を無効化   | 認証・研究同意・識別情報の除去・保存・集計抑制へ依存                               |
| 永続保存                   | 高     | 各機能の継続利用・再開ができない                         | 認証・患者・運営・研究の各機能が依存                                               |

各機能のRTOは10分、保存するアカウント・同意・入力・対話・カード・評価・管理情報等のRPOは10分。重要度は業務影響の分類であり、今回ユーザーが共通指定した復旧目標を変更しない。実際の配置単位・監視・復旧手順は後続設計で対応付ける。

## 運営機能の追加（2026-10-29の変更依頼）

ユーザーの追加指示に基づく要件差分。従来のアカウント状態管理・研究者権限管理に加え、次の操作を運営へ付与する。

- FR-13: 運営は管理者用Web画面で、お知らせの作成・編集・下書き保存・発行・公開／非公開の切替を行える。利用者は公開された内容だけを取得できる。公開対象と表示場所は後続設計で具体化する。対応: US-22。
- FR-14: 運営はメンテナンス時に対象ページを非公開にして通常のページ遷移を停止し、アクセス時にメンテナンス案内を表示できる。直接URLも制限対象とし、終了後は再公開できる。対象ページ・関連API・進行中の操作の扱いは後続設計で具体化する。下書き保持と再開、役割・同意によるアクセス制御を維持する。対応: US-23。

これらの変更操作は運営権限を確認し、研究者権限のみでは許可しない。本番変更の記録・承認・切り戻し・事後確認はNFR-06に従い、計画停止もNFR-05の停止時間に含める。既存の可用性・復旧目標は変更しない。今回の追加はストーリー成果物全体の承認を意味しない。
