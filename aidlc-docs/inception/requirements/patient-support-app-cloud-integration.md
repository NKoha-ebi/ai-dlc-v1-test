# 患者支援アプリのクラウド接続要件

2026-11-21。既存の患者支援アプリを get-check-1120 で動かす。共通ゲートの先行検証を省くという既存判断を踏まえ、初回配備はアクセスを限定し、合成データで機能を確認する案とする。

## 要件

- Cloud Run で既存の React 画面とサーバー API を提供し、患者の登録、ログイン、悩み入力、対話、再開、退会の導線を確認する。
- 悩みの整理、対話、要約をサーバー側の OpenAI Responses API に接続する。送信情報を必要な相談文脈と注意事項に絞り、共通および選択したがん種の注意事項を適用する。診断・治療の判断を提供しない。既存方針に合わせて store: false を指定する。
- OpenAI API キーを Secret Manager に置き、Cloud Run の実行 ID に対象シークレットへのアクセスを付与する。ブラウザー、リポジトリ、ログにキーを載せない。エラー時は状態を保持し、再試行できるようにする。
- Firebase Authentication とアプリ専用 Cloud Firestore を候補とする。患者 ID 単位でプロフィール、同意、悩み、対話、まとめを分離する。既存の安全台帳 DB と区別する。再ログイン・再配備後の復元、別アカウントからのアクセス拒否、退会後の削除を確認する。
- 初回は東京を候補に、合成の相談内容で実 API 応答・保存・再取得・削除を確認する。処理地域、保存期間、利用上限、外部送信条件、HTTPS ロードバランサーの構成と費用は後続の構築計画に記載する。実患者データでの利用と公開切替は既存設計の条件に従う。
